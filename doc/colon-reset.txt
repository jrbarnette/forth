While compiling a definition, we can need up to three distinct values
associated with the definition:
  * The value of `HERE` prior to starting the definition.  We need this
    to know where to reset if there's an error during the definiton, and
    we want to roll back.
  * The name pointer of the definition, for linking when we get to the
    end of the definition.  For `:NONAME`, we use 0 to indicate that
    there's no name to link.
  * The actual XT of the definition, for use by `RECURSE`.


The values are distinct but interrelated: if we know the saved `HERE`
value and one other, we can calculate the third.

... It would also be nice to have a way for `;` to check whether there's
a definition open, in order to report an error.

Assume we put all of the data into a structure:
    variable DEFINITION-DATA 2 cells allot
    0 definition-data !

We'll need these helpers:
    : open-definition
	rot definition-data !
	[ definition-data cell+ ] literal 2! postpone ] ;
    : close-definition 0 definition-data ! postpone [ ;
    : definition-xt [ definition-data cell+ ] literal @ ;
    : definition-name [ definition-data 2 cells + ] literal @ ;
    : rollback-definition
	definition-data @ ?dup if here - allot then
	close-definition ;

And the CORE functions would look like this:
    : : here hdlr-colon start-name dup name>xt open-definition ;
    : ; postpone EXIT
	definition-name ?dup if link-name else definition-xt then
	close-definition ; compile-special
    : RECURSE definition-xt compile, ;

    : :NONAME here align 0 here hdlr-colon , open-definition ;

Then when we need to roll back a failed definition, we do the following:
    : handle-exception ( throw-code -- )
	.throw-code clear rollback-definition ;

(Question: is this all we have to do to roll back a failed definition?)
(Note: roll back only happens if `QUIT` sees an exception _and_ there's
an open definition.)

... The changes above will require that all of the existing code that
assumes there's something on the stack during :-definition needs to be
adjusted :-(
